# NoLang Draft Studio

The writing system — the four compression rules, the studio commands, the asset rules, the grammar differences, the spelling map and what cannot be written — lives in **`libs/ai/llm_prompts/draft_author/reference/spec.md`**. Read it first; everything below assumes it. That directory (below: `REF/`) is the single source of the grammar documents the product's three roles read (`contract.json` names the set): the dictionaries `REF/authoring.md` · `REF/capabilities.md` · `REF/looks.md` · `REF/sounds.md` · `REF/craft.md`, the samples `REF/samples/` and the scaffolds `REF/scaffolds/`. This skill dir's own `reference/` keeps only the dev docs (compare.md · formats.md · stream.md).

## Prerequisites (environment)

- The same dev container that runs the product locally: `/opt/venv` python, Django with the LOCAL DB (`.env`), and the asset catalogs (fonts, speakers, BGM, sound effects, standing pictures) loaded with `manage.py seed`.
- resource-service (svg / html drawing; separate repo `nolang-resource-service`; `PORT=9500 npx tsx bin/server.ts`; reached via `RESOURCE_SERVICE_URL` or localhost:9500). When it is down, render stops with a one-line notice.
- The gpulibs native build (`docker_setup/build_gpulibs.sh`). The render encoder and HLS use CUDA, so a GPU is required (check needs none).
- In a worktree, symlink `.env`, `static/credentials` and `build_gpulibs` from the main checkout. `make link-skills` shows the skill to Claude Code (per clone / worktree).
- The resident server (`studio_server.py start`) is optional. Without it each command boots Django itself (about 7 s slower each).
- stream (below) calls the author and the staff via `claude -p`, so the machine must be logged in to the claude CLI (runs on the subscription allowance; one video is worth $0.7–2.7). Environment `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` take precedence over the login, so unset them for the author (left set, you get a 0-token response, `author exit 1`, `cut 0`, and the reason in `stream/claude_author.err`).

## Process (resume from the project's state)

- No `brief.md` → read the request and write the brief (format: `reference/formats.md` §brief). If the request has a script, copy it into the brief and use it as-is from then on.
- No `storyboard.md` → write the storyboard from the brief (§storyboard). frame = cut. For each frame decide "the screen's most visible moment", the speech, the changes tied to words, and the length. No grammar at this stage.
- No `studio/` → read the two samples of your type in `REF/samples/` (one winning NoLang src + one `hf_*` port of hf's build) → make the skeleton with `new` → **the design system once in the root** (`palette` `font` `fonts` `motion` `art` plus the `def`s (= classes) for headings, body, cards and boxes (card rows, horizontal bars, flow-chart cards)) → copy the storyboard's frames one by one into `section#名` and `*** 名` (§build).
- No `out/video.mp4` → run `check` down to DEFECT 0 · severe 0 (read the warns and fix what you can) → `render` once.
- Everything there → report (§report). No round trips of reading frames after render to fix things.

## Process rules

- **The brief is law**: one message sentence · audience · arc · format · three look words · voice · must / avoid. Later judgments go back to the brief.
- **The storyboard designs structure, not looks**: each frame has exactly one "what this frame makes clear". A frame's length comes from its speech (4–25 s).
- **Design system first**: as in hf, decide the colors, fonts, text scale, and card / box classes in the root before writing frames. Frame elements apply the classes and write only their differences.
- **Build frame by frame**: 1 frame = a `section#名` design + a `*** 名` speech. Write the frame's "most visible moment" into the design (elements at their fully shown positions and sizes; absolute placement is fine); the entrance is the road there, and the word marks are that moment's changes.
- **Review on check's output**: in the showing-times table, read per frame whether heading → body → changes follow the speech (changes = every mark you wrote · defaults = motion the engine added). Post-render frames are for the report only.

## Loop (one render)

1. Write in the process order (above) → `check` down to DEFECT 0.
2. Reading check: DEFECT = a grammar error (with file:line and the fix; cannot draw) · severe = draws but breaks (fix it) · warn = fix · info = reference. The showing-times table = whether elements are tied to words (its changes column lists every `[!#名]` `[=#名]` you wrote · the defaults column is motion the engine added). The expansion table = def instances' and ×N children's names, boxes and text sizes (marks and position expressions `名.right+8` resolve against these names). `css` warns = dropped declarations (drawn as if absent).
3. `render` once. When a report mentions a visual issue, Read that frame (`out/render_frames/`) and write it with its seconds.
4. For a full-length critique, hand the `tmp/critic/make_sheets.sh out/video.mp4 <dir>` sheets to the subagent `video-compare-opus-medium` (reference/compare.md).
5. Audio runs on `listen` (after render; `--apply` goes as far as redrawing): each cut's audio is played twice to Gemini 3.8 Flash; sounds that do not fit the scene (drops agreed twice) and hammered repeats (repeat) are recorded in `listen.json`, and the next render leaves them out. Loudness is not judged by ear (the engine measures the floor and anchor). Details in `REF/sounds.md`.

Rule names and fixes (generated from the two ledgers, check's `draft_check/rules.py` and the product's `quality_rules.py`; silence a rule that does not fit the piece with `lint off=<rule>,…` in the root): `empty_cut` place a picture or a card・`shrunk` change the width or the text size (widen the frame / drop `width:` to fit the text / shorten the wording)・`offcanvas` (severe) move the position inward・`duplicate_text` a card with the same text as the subtitle → put short key words on screen instead. A card that shows the speech itself (lyric-video lines, speech bubbles) takes `.hide_subtitle` (the subtitle is not drawn while it shows; with `lint off` the two stay side by side)・`text_overload` more text than the cut's length lets the viewer read → trim the wording to short key words; show it in turns on the words instead of all at once (close the earlier card with `[<#name]`; do not split the cut)・`spoiler` a heading shows a speech word early → bring it in on its word's mark・`still_stretch` nothing moves for 6+ seconds (a picture's kb does not count as motion) → add marks on words・`long_still` (info) the screen does not change while speech runs 3+ seconds → mark a word in that span・`cut_head_gap` the cut's head is empty for 1.2+ seconds → place the head elements without marks・`entrance_in_fadeout` it enters too late before the transition or fade out to be read → move the word earlier (a short stamp landing on the last word reads in time and rides the transition — that is fine)・`entrance_in_transition` a word mark's entrance finishes inside the previous transition's window → add `[silence:+0.4s]` at the head of the first speech to push the word past the window (check says the seconds needed)・`no_closer` the last cut has no big closing line・`same_picture` the same picture for 15+ seconds → swap to another picture, diagram or card on a word inside the cut (do not split the cut)・`blank_band` a third of the screen is bare ground at the cut's head → lay a full-bleed picture, or put a card on the band・`dip_black_frame` dip means black frames → dissolve or wipe・`double_exit` a cut that ends on a transition also has a whole-cut out, so the scene fades and then the transition runs (it dies twice) → to end on a fade, make the transition `transition cut`; if the transition carries the scene, drop the section's out (for a transition inherited from the root, the machine turns it into a cut)・`persistent_chrome` persistent layers (progress / chapter numbers / running totals) belong only in videos of 3+ minutes — in a short video the cost of occupying a screen edge outweighs them, so drop it・`sparse_cut` 4+ seconds with few elements → add a picture or a card・`palette_drift` inline colors in hues off every root palette hue (tints and shades of a palette hue do not count) → add the hue to the root's `palette`・`low_contrast` little contrast between text and its ground (also after a dimmed `dim` / focus sibling or `recolor`) → dim deeper・`overlap` text of the same family overlaps (warn even with `overlap:` declared; hiding another family's text is the severe occluded) → move the stamp / card off the other text・`title_on_close` the first cut's title is never closed and remains in the last frame → `[<#name]` (to restate the name at the close, make a new layer in the closing cut)・`leaks_into_next_cut` (info) other layers exit before the transition and only the out-less layer remains into the next cut's head (the default is that everyone rides the transition alive — only the author's out divides who stays and who goes) → to align them, write out on the other layers too, or drop this one's out・`orphan_line` the wrap's last line is 1–2 characters (「本気だっ / た。」) → tighten the wording, shrink the text, or break with `[br]`・`overridden` the engine changed a written value (with a cause) — subject_clear: place the text off the picture's subject / icon_square and late_admission: the engine's alignment (no fix needed)・`transition_over_speech` the transition overlaps speech・`se_dense` sound effects are dense (`sfx off`)・`running_total` a running-total card's value decreases across cuts → copy the totals written in the plan・`font_not_pinned` the font could not be resolved as in production and was measured with the default font (run check where the DB is; bring the font description closer to a catalog font)・`synthetic_bold` the family has no bold face (there is no browser synthetic bold) → pick a family with weights via `font-family:` or drop the font-weight・`ghost_dissolve` in a 400 ms+ dissolve, the previous cut's large text or picture shows through into the next cut (a layer without out, or a transition dissolving from before the boundary) → set `overlap=` equal to the duration (text with out finishes fading by the boundary); pictures and cards without out take `[<#name fade]` at the cut's end・`photo_hidden` a veil of opacity 0.7+ covers 90%+ of a full-bleed photo for 3+ seconds (the photo washes out / sinks dark) → move the photo to one side (text on the ground side), or cap the veil at 0.6 and put a band / board only under the text。

## Making with stream (the product's pipeline — one video from a request)

```bash
bash agent_client/scripts/stream_make.sh tmp/studio/<name> --type concept --aspect 9:16 --request <依頼文の file>
bash agent_client/scripts/stream_make.sh tmp/studio/<name> --edit <video_id> --request-text "<直す点>"   # 完成した動画を直す (下)
```

`--edit <video_id>` edits a finished video instead of writing a new one: the author is skipped, and an editor (Opus · medium · 1 call) reads the video's stored src plus the request and re-emits only the cuts the request touches (per request item it answers patch / rebuild / asset / impossible — `edit/verdict.json`). Untouched cuts submit byte-identical with no staff and no check (they shipped once already); changed cuts get check → fix; only inserted cuts get the staff; a root change re-checks every cut. A rebuild-class item (target seconds, aspect ratio, whole-style conversion) or an editor failure falls back to the author lane with the video as reference (same as `--ref`), and a request with nothing to patch exits 0 after `edit: 変更なし`. `--type` is not needed (aspect follows the parent); `--speech` / `--author-brief` do not combine. Mechanics in `reference/stream.md`.

The author (Opus · low · 1 call) streams the src in cut order; per cut the staff (Opus · medium) finishes it to a professional explainer's density and hierarchy, then check → fix (up to 2) → assets (pictures · voice) → seal → submission, and so it
advances cut by cut. Drawing is the product's DraftStreamRun (`studio.py stream` · one process on this machine) extending the HLS per seal. From the moment the first cut is sealed (90–110 s on a quiet machine)
HLS segments (`static/video_generate/<process>/`) accumulate, and with all cuts done you get `studio/out/video.mp4`. Named definitions (def · motion · run · svg · sound · image · cue) are written in the block of the cut that first uses them,
and only that cut fixes them. The root (settings · cast · the subtitle and BGM opens · persistent layers) is owned by the first cut and freezes when that cut is accepted.
Times are in `stream/run.jsonl` (`first_segment` / `manifest_published` / `final_ready`, plus per cut `staff` `check` `fix` `warm` `submitted` `sealed_ack`); the author's version before the staff is
`solo/author_cut_<名>.txt`, and each cut's doc and check live in `weave/<cut>/` (the doc is a window = root + first cut + previous cut + this cut + the cuts that opened still-open spanning layers; definitions outside the window sit behind the root). `--no-staff` is no staff (fast, quality drops) · `--staff balanced` (the default; `--seconds` also defaults to `auto` = the author sizes the video to the script, matching `nolang make`) is staff low on cuts 1–2, and from cut 3 on medium only when its predicted finish beats the viewer's arrival at that cut, low otherwise (stall-free start median ~130 → 90 s · a small quality drop · all-medium tails stalled 4 of 10 runs) · `--staff low` also works · `--staff-warn` passes warn findings to the staff too (the default is DEFECT and severe only). Efforts: author `--effort` · staff `--staff` · review `--review` (default low · `medium` allowed — the first fixer pass over every cut acts as a strict director hunting weak spots and breakage the findings do not name; the review always sees cut stills and every severe/warn finding, and runs once (`reference/stream.md`) · `none` for off) · fixer `--fix` (default `severe` = only DEFECT and severe findings (hidden text, offscreen …) call the fixer at low, no review, warns stay unfixed · `defect` = DEFECT and hidden text only · `none` for no fixer at all · `low` for the review plus fixing findings). By default the staff changes neither pictures nor speech, and pictures and voice are built from the author's version in parallel with the staff (`--staff-edits-assets` lets the staff edit both · `reference/stream.md`). The three roles' prompts are not rule bundles but a professional's brief + grammar + craft (`REF/craft.md`) (10-23 · `reference/stream.md`). Samples default to the two `hf_*` of your type in `REF/samples/` (excluding ones on the request's own topic, same orientation first, first by file name).
To change them: `--samples a.md,b.md` (a previous run's `stream/samples.txt` passes as-is). Quality evidence: `docs/draft_src_v2/stream-evidence-261013.md` and the "3 役の prompt" section of `reference/stream.md`.
To hand drawing to the NoLang server: `--remote http://<api> [--token nlg-c-…]` (assets, drawing and delivery go to the product's draft stream renderer; this machine runs only the author, staff and fixer). The token is an API key, or the token Claude Code obtained on connecting to NoLang via `/mcp` (OAuth · `mcp.json`) (used automatically when omitted). Outside the repo (the skill installed as a plugin) only `--remote` works, and check / renames / the rules ledger arrive from the API (the skeletons are `reference/scaffolds/`; plain `python3` suffices). When the plan appears you get `WATCH <url>` (the video page, chasing playback). When a viewer can start playing (status `playable`) you get `PLAYABLE <url>`. A local run (no `--remote`) calls the same receiving ends (submission · warm · check) locally, so the stages and the check findings are identical. The contract is `app_main/docs/feature/video_generate/external_author.md`. If the request carries fixed assets (this photo, this song, this voice), search with the MCP `nolang_assets_search` (scope=mine is your own uploads) and upload local files with `python3 agent_client/scripts/upload_asset.py <file>… --remote <api>` (with the plugin, the skill dir's `scripts/`) (it prints `REF <file> id=<uuid>`; videos wait for finishing, tens of seconds). Write that `ref` (`id=<uuid>` etc.) in the request and the author copies it straight into `image 名 = id=…` / `bgm#名 id=…` / `cast 名 = id=…`.

## Dictionary and how to wait

Read `REF/authoring.md` by section line numbers (Read's `offset` / `limit`): L7 HTML form · L16 Tokens · L33 design.txt · L62 Types · L77 Position · L95 Motion · L106 def and root templates · L165 Subtitles and cuts · L169 timeline.txt · L199 Marks · L218 Timing rules · L227 Cues and transitions · L233 Defects (key names are listed in v2 spelling — `size` `fill` `radius` `shadow` … — but the CSS names `font-size` `background` `border-radius` `box-shadow` … work as written).
render runs in the foreground as `timeout 900 $P $S …`. Sharing the GPU, prefix `STUDIO_RENDER_LOCK=<file>`. If resource-service is down, start it (Prerequisites (environment)).
To compare two videos: `reference/compare.md`.
The evidence for this skill's shape (4 compression rules + 5 differences + the process + samples) is `docs/draft_src_v2/studio-skill-evidence.md`.
